## 0. Executive summary — the decisions

| # | Question | Decision | Why (short) |
|---|---|---|---|
| 1 | Binding strategy | **Hand-written `extern` core (~20 fns) + comptime two-family ABI layer** (MPICH-family / Open MPI), selected by `build.zig` probing `mpicc`. MPI-5 standard ABI added later as a third family, not the default. | Only ~20 functions needed; translate-c (Aro) is young in 0.16, chokes on Open MPI's link-time constants, and JIT-compiles for minutes on first use. Cray MPICH has no standard ABI yet. (§3) |
| 2 | Decomposition | **MPI is strictly inter-node (1 rank per node × the P1 thread team) and splits φ only**: a 1D periodic ring of NTZ φ-slabs via `MPI_Cart_create`. 2D (`nz==1`) never decomposes; **θ and r are never decomposed** (r-splitting is the documented growth path if node counts must ever exceed the φ cap). | φ is periodic (no axis/BC complications), cost-uniform (the torus is axisymmetric → near-perfect static balance), r staying whole keeps every radial diagnostic/BC/scale-height subtlety rank-local, and φ-slabs are *contiguous* in our AoS layout — which makes the exchange zero-copy. (§5) |
| 3 | Exchange protocol | **Single-stage, two neighbors (φ±), two messages — zero-copy**: persistent send/recv channels bound *directly* into `Field.data` (φ-slabs are contiguous, ghost-extended planes included), `Startall` + `Waitall`. **No pack/unpack, no buffers, no team involvement.** | The AoS iv-fastest layout makes a φ-slab one contiguous block; sending full SX·SY planes costs 3.3% extra bytes and deletes the entire pack machinery. Persistent + pre-post is unanimous across modern codes. (§6) |
| 4 | Exchange placement | Exactly C's: before each `opExplicit` (between `doCorrect` and `setBc`, [sim.zig:1775-1776](../koral/sim.zig) and :1801-1802) and inside `applyDynamo` ([dynamo.zig:388-389](../koral/magn/dynamo.zig)). **Never inside `setBc`** (it runs ~9×/step). | 5 | Collectives | **One `Allreduce(MAX, [tstepdenmax, −tstepdenmin, n_radimp_fail])` per step, at the *end* of `step()`**. Scale-height: two pre-`sqrt` partial-sum Allreduces over the cart comm — with φ-only decomposition **the world *is* the φ-ring**, so no sub-communicators exist anywhere (3D only — 2D runs are single-rank). Scalars become proper reductions (fixing C's "disabled under MPI"). | `pmpio.h` is a self-contained header over plain Send/Recv — verified in the vendored Silo 4.12 tree; the baton is trivial to write against our own bindings. (§8.2–8.3) |
| 8 | Thread level | `MPI_Init_thread(MPI_THREAD_FUNNELED)`; only the main thread calls MPI, between team regions (the zero-copy exchange needs no team work at all). | Matches the team's main-thread-only contract ([threading.zig:178-180](../koral/sim/threading.zig)); THREAD_MULTIPLE is the documented hybrid bottleneck and buys us nothing. (§6.3) |
| 9 | Solver flags in halos | Phase A: **not exchanged** (C-faithful; seam-dependent fixup accepted and documented). ## 1. Where the code stands today

The seam exists but is **decorative**: [comm/serial.zig](../koral/comm/serial.zig) defines `Serial{rank,size,exchangeHalos,allreduce,barrier}` with **zero call sites** anywhere in the numerics; `Sim` has no comm field, and `-Dmpi` deliberately `@compileError`s ([koral.zig:9-16](../koral/koral.zig)). This is good news: the API can be *replaced*, not implemented — `exchangeHalos(comptime T, []T)` cannot express "NG-deep slab of a `Field(NV)` with corners" and was never called.

What the retrofit must integrate with (full map in the surprises list, §1.1):

- **Grid** ([grid.zig](../koral/grid.zig)) has no global-vs-local notion, no tile origin, and derives `dx = (maxx−minx)/nx` at [grid.zig:57-59](../koral/grid.zig) — localizing `nx` without localizing extents silently rescales the mesh (§5.2).
- **Step loop** ([sim.zig:1729](../koral/sim.zig) `step()`): RK2-IMEX with the three canonical exchange sites (§6.1). `setBc` is called ~9×/step (from `calcU2p`, `opExplicit`, `applyDynamo`) — exchange must not live there.
- **Threading team** ([sim/threading.zig](../koral/sim/threading.zig)): persistent futex-parked workers, `parallelRange(Ctx, ctx, team, lo, hi, worker)`, main-thread-only and non-reentrant — MPI calls slot between team regions on the main thread. (With the zero-copy φ exchange the team plays no role in communication at all; it re-enters only for the P4c pole pack.)
- **I/O**: KDMP checkpoints ([io/dump.zig](../koral/io/dump.zig)) hard-fail on any dimension mismatch (:119); Silo export is one `DBfile`/one mesh; scalars ([io/scalars.zig](../koral/io/scalars.zig)) are whole-domain loops. C simply *disables* scalars under MPI — we fix that instead (§8.3).
- **Params** ([params.zig](../koral/params.zig)): runtime TOML-subset; `nx/ny/nz` become **global** dims; `ntz` lands here (not in the comptime `Config`); `deterministic` exists and is currently wired to nothing.

### 1.1 The retrofit traps (verified, file-precise)

1. **`dx` must be computed once from global extents** and the local `minx = minx_global + toi·dx` — else the metric cache diverges across ranks ([grid.zig:57-59](../koral/grid.zig), `xl()` at :113 is the entire coordinate system).
2. **Polar machinery is local-index**: `isCellCorrectedPolaraxis(iy)` ([sim.zig:496](../koral/sim.zig)) gates u2p/fixup/implicit; `polarCols` overwrites rows `[0,nc)∪[ny−1−nc,ny−1]`. Under a θ-split every rank would "own" both poles. **Fix: θ is never decomposed** (§5.1) — the tests stay correct as written.
3. **PUFFY's `specific_bc` reads local `nx/ny` as global** ([puffy.zig:766+](../koral/problems/puffy/puffy.zig)) — **defused by φ-only decomposition**: x and y faces are *always physical* (r and θ never split), so the radial/polar BCs keep their exact semantics untouched. The `isPhysicalBoundary(face)` gate (C's `mpi_isitBC`) matters only for the z faces: with NTZ>1 the periodic-φ wrap ([sim/bc.zig:194-197](../koral/sim/bc.zig)) becomes the interior exchange and `setBc` skips z entirely; with NTZ==1 the serial self-wrap path runs as today.
4. **Scale height is a cross-rank sum**: `scaleth[ix]` is a θ,φ column sum ([dynamo.zig:158-211](../koral/magn/dynamo.zig)) — needs *pre-`sqrt`* partial-sum Allreduces over the φ ranks. With r whole, `toi == 0` always, so the C quirk "gix==0 keeps the raw sum" needs **no change at all** — the existing local test is already the global one. 3D-only concern — 2D runs are single-rank.
5. **`postinit` BETANORM is a global max** ([puffy.zig:717-718](../koral/problems/puffy/puffy.zig)) — without an init Allreduce every rank normalizes B differently and the field is discontinuous from step 0. Same for `min_dx/dy/dz` ([sim.zig:363-386](../koral/sim.zig)) feeding `initTimestepGuess`.
6. **dt collective placement**: the driver calls `s.cflDt()` *before* `s.step(dt)` ([puffy/main.zig:523](../koral/problems/puffy/main.zig)) — the reduction must land at the **end of the previous step**, not the top of the next.
7. **`cellFixup` clips neighbors at local bounds** ([sim.zig:941-947](../koral/sim.zig)) and flags are not exchanged — fixup at tile seams is decomposition-dependent *by construction* (C-identical). Accepted in Phase A, optional flag exchange in Phase C (§6.4). The `anyFlagSet` early-out (:842) also makes per-rank pass timing asymmetric — an inter-rank imbalance the intra-rank tiles can't absorb; harmless numerically.
8. **A whole-domain bitwise 2×1-vs-serial diff will NOT pass, and that's correct**: serial periodic runs fill 1-deep ghost corner *surfaces* by copying the adjacent domain row (C `finite.c:3213`), while an MPI run exchanges corners exactly — divB at former-seam corners legitimately differs (`MILESTONES.md:55-63`). The validation ladder (§10) tests interiors bitwise and seams at field-scale tolerance.
9. **`emf` arrays are domain-only with unsigned asserts** ([sim.zig:470](../koral/sim.zig)) — fine: flux-CT is Tóth cell-centered ([magn/ct.zig](../koral/magn/ct.zig)), each rank computes EMFs on its own faces from exchanged primitives; no EMF messages and no polar-EMF ring are needed (those belong to staggered-CT schemes like Athena++'s).
10. **`build.zig` has no `linkSystemLibrary` anywhere and the dev module lacks `link_libc`** — both must be added under `-Dmpi`, including for the test artifact (which shares the `koral` module and will need an `MPI_Init` bracket or a comptime carve-out).

## 2. What production codes do (survey synthesis)

Ten MPI layers were profiled from source (2026-08 checkouts): iharm3D/ebhlight/nubhlight, Athena++, AthenaK, KHARMA/Parthenon, PLUTO, Idefix, MPI-AMRVAC/BHAC, H-AMR (papers), AMReX, and original KORAL. Condensed:

| Code | Decomposition | Exchange | Threads | Pole (3D) | Restart I/O |
|---|---|---|---|---|---|
| iharm3D/nubhlight | static Cart tiles | staged/dim, blocking Sendrecv, subarray datatypes, **pflag in halo** | FUNNELED+OpenMP | local reflect | shared parallel HDF5 |
| Athena++ | MeshBlocks, Morton SFC, **measured-cost EWMA rebalance (opt-in)** | direct 26, manual pack, **persistent reqs**, Iprobe nudge | MULTIPLE (w/ OMP) | π-shift pairing + sign tables (+ EMF ring for staggered CT) | shared MPI-IO, fixed blobs, `write_at_all` |
| AthenaK | MeshBlockPacks (1/rank) | direct 26 → **one aggregated msg per rank pair** (2026) | flat MPI+Kokkos | none (Cartesian KS + excision) | shared MPI-IO fixed blobs |
| KHARMA/Parthenon | MeshBlocks SFC | CommBuffer state machine, Iprobe nudge, coalesced opt | flat MPI | transmit only if φ-ring local; **`pflag`/`solve_fail` as ghost-exchanged fields**; ISMR pole-averaging | collective parallel HDF5 |
| PLUTO | ArrayLib Cart | staged, blocking, datatypes, per-variable (anti-pattern) | flat MPI | local reflect | shared collective MPI-IO |
| **Idefix** | Cart, static | **staged + persistent reqs + pre-posted recvs, fused all-var buffers** | flat MPI+Kokkos | **φ-ring `Cart_sub` + `Cart_shift(nφ/2)` partner, persistent cross-pole exchange** | shared collective MPI-IO via subarray views |
| AMRVAC/BHAC | octree SFC (BHAC: 3:1 weighted cut) | direct 26; BHAC packed 1 msg/neighbor, recvs pre-posted | flat MPI | π-shift as connectivity, **receive-side transform** | BHAC parallel `write_at` |
| H-AMR | blocks + SFC + LAT | GPU pack, nonblocking | CUDA+OMP+MPI | transmissive + **static φ-coarsening near axis** | parallel, nonblocking |
| AMReX | BoxArray+DM, knapsack w/ measured costs | **cached canonically-sorted tags, 1 aggregated msg/rank-pair, corners default** | plain Init; OMP in tiles | `FillPolar` as cached metadata | NFiles (N→256 files, dynamic writers) |
| KORAL (C) | static tiles | direct 26 hand-packed, **sends before recvs (anti-pattern)** | flat (MPI⊕OMP exclusive) | TRANSMITTING_YBC π-shift; world-Allreduce axis avg (wasteful) | shared independent MPI-IO |

**The consensus core (unanimous):** static decomposition fixed at startup; two-sided *nonblocking* point-to-point only (no RMA, no neighborhood collectives in any halo path); receives pre-posted before packing; manual packing into contiguous fused buffers (every post-2015 code; BHAC deliberately migrated *away* from datatypes — datatypes survive only in MPI-IO *file views*, where they're free); one shared restart file with offsets computed from the static decomposition; dt via one `Allreduce(MIN|MAX)` per step; the π-shift pole partner as ordinary connectivity with θ-reversal + per-variable sign tables.

**Where the survey bears directly on us:** (a) solver-flag halos have production precedent exactly where per-cell solvers live (iharm3D `pflag`, KHARMA `solve_fail`) — but iharm3D pays a *second full sync per substage* for flag coherence; the lesson is to fuse flags into the same message, not add a sync. (b) Nobody ships our exact hybrid (static ranks + persistent FUNNELED team + dynamic intra-rank tiles) — the fragments are each validated (Athena++ `schedule(dynamic,1)` over blocks; AMReX dynamic `MFIter` tiling; BHAC's Cielo-2022 recipe of threading ghost-independent work during the `Waitall`) but combined nowhere. Our plan is a refinement of documented practice, not a gamble. (c) Anti-patterns to design out, all observed in the wild: sends-before-recvs (C KORAL), barriers bracketing exchanges (PLUTO, C init), per-variable exchange loops (PLUTO), an extra sync to launder fixup non-determinism (KHARMA `two_sync`), per-call buffer allocation (BHAC), rank-0-funneled snapshots (AMRVAC 3.x).

**What we explicitly do NOT need** (AMR baggage): restriction/prolongation ghost rounds, flux-correction/refluxing (uniform grid — fluxes match by construction), octree metadata/regridding/migration, sparse-buffer negotiation, metadata invalidation. On a static uniform grid, *all* communication metadata is computed once, ever — which is also why AthenaK/AMReX-style "aggregated message per rank pair with a build-once offset table" collapses, for us, into simply "one fused buffer per neighbor": at one tile per rank they are the same thing.

## 3. Zig ↔ MPI bindings (`comm/mpi/`)

### 3.1 The ABI problem, 2026 status

Two incompatible C ABI families exist: **MPICH-family** (MPICH, Intel MPI, MVAPICH, Cray MPICH — the `libmpi.so.12` compatibility initiative; handles are `int`, predefined constants are compile-time hex values) and **Open MPI** (handles are struct pointers; `MPI_COMM_WORLD` is the *address of an extern symbol* — a link-time value that cannot be a Zig comptime constant). The MPI-5.0 **standard ABI** (ratified June 2025: pointer handles, standardized constant bit-patterns, 8-int `MPI_Status`, `libmpi_abi.so`) is shipping — MPICH 5.0 (GA 2026-02), Open MPI main (merged 2026-08-05, targeting 6.0), Intel preview — but **Cray MPICH 9.1 (CPE 26.03) is still MPICH-4.2.2-based with no standard-ABI timeline**, so it cannot be the only path for 1–2 more years.

Verified per-family differences that the binding layer must own:

| Item | MPICH family | Open MPI |
|---|---|---|
| `MPI_Comm` etc. | `int` (comptime constants: `MPI_COMM_WORLD = 0x44000000`) | `struct ompi_communicator_t*` (`&ompi_mpi_comm_world`, **link-time**) |
| `MPI_Status` | 20 B, `MPI_SOURCE` at offset 8 | 24 B, `MPI_SOURCE` at offset 0 |
| `MPI_IN_PLACE` | `(void*)−1` | `(void*)1` |
| `MPI_STATUS_IGNORE` | `(MPI_Status*)1` | `NULL` — **never model status params as Zig optionals** |
| Thread-level consts | 0..3 | 0..3 (same — shareable) |
| `MPI_File` | pointer (ROMIO) | pointer — pointers everywhere for MPI-IO |

### 3.2 The design: extern core + comptime family layer

No existing Zig MPI binding is production-grade (six toy repos total), and 0.16's translate-c (now Aro-based, `@cImport` deprecated) chokes on Open MPI's `OMPI_PREDEFINED_GLOBAL` macros and JIT-compiles itself for minutes on first use — keep it out of the build path. For ~20 functions, hand-written externs are decisively right (this is also rsmpi's architecture, minus bindgen, which Zig doesn't need):

```
koral/comm/mpi/
  abi.zig          — comptime-selected family: pub const Family = enum { mpich, ompi, std_abi };
  abi_mpich.zig    — handle typedefs (c_int), Status extern struct, sentinel/constant table (~60 lines)
  abi_ompi.zig     — opaque-pointer handles, extern predefined symbols + init-time resolution (~60 lines)
  abi_std.zig      — MPI-5 ABI (later; all constants comptime again — one file replaces both)
  core.zig         — the ~20 extern "mpi" fn declarations (signatures are family-invariant)
  mpi.zig          — pub const Mpi = struct {...}: the Comm backend built on core+abi
```

Handles get mpi_f08-style distinct wrapper structs (`pub const Comm = extern struct { h: abi.RawComm };`) — type safety at zero cost, and the family types never leak past `comm/mpi/`. The function subset: `Init_thread, Finalize, Abort, Comm_rank/size, Cart_create/coords/shift/sub, Isend, Irecv, Send_init, Recv_init, Startall, Waitall, Allreduce, Iallreduce (later), Reduce, Bcast, Barrier, File_open/close/set_view (or write_at_all/read_at_all), Wtime`.

Selection is comptime: `build.zig` probes the system and sets `build_options.mpi_family`. A CI-able self-check compiles a 10-line C program against the found `mpi.h` printing `sizeof(MPI_Status)`, `offsetof(MPI_SOURCE)`, and sentinel values, compared against the Zig-side table — cheap insurance against vendor drift.

### 3.3 build.zig discovery

Probe order (all mechanisms verified available in Zig 0.16's `std.Build`):

1. Explicit overrides: `-Dmpi-include=… -Dmpi-lib=… -Dmpi-family=mpich|ompi`.
2. `b.findProgram(&.{"mpicc"})` + `b.runAllowFail`: parse `mpicc -show` (MPICH/Intel) or `mpicc --showme:compile/--showme:link` (Open MPI) for `-I/-L/-l/-Wl,-rpath`.
3. `$CRAY_MPICH_DIR`/`$MPICH_DIR` (CPE systems have no mpicc; also `pkg-config` via `mpich.pc` there — the rsmpi route).
4. `linkSystemLibrary("mpi", .{})` (pkg-config) as last resort.

Family detection: grep the found `mpi.h` for `MPICH_NUMVERSION` vs `OMPI_MAJOR_VERSION`. Under `-Dmpi` the koral module and every problem exe get `link_libc = true`, the include/lib paths, `-lmpi`, and an rpath to the MPI lib dir. Remove the `@compileError` guard in [koral.zig:9-16](../koral/koral.zig) and select `pub const Comm = if (build_options.mpi) @import("comm/mpi.zig").Mpi else @import("comm/serial.zig").Serial;`. The `zig build test` artifact stays serial by default; MPI-specific tests live behind `-Dmpi` with an `Init/Finalize` bracket (§10).

Dev machines: `brew install open-mpi` (macOS, Open MPI family) gives the full 4-rank test environment locally — the OMPI ABI file gets exercised on every dev box, the MPICH file in cluster CI.

The team reads its **actual** cpuset — `sched_getaffinity(0)` (not env vars), spawns `CPU_COUNT(mask)` workers, and pins worker *k* to the *k*-th allowed CPU (`pthread_setaffinity_np` / raw `sched_setaffinity` via `std.os.linux`; intersect with the inherited mask — setting a CPU outside the cgroup cpuset returns EINVAL). Because the rank now spans **all** of the node's NUMA domains, first-touch is no longer automatic: field and metric-cache pages must be first-touched by the worker that will own them under the runtime tile partition — the P1-deferred NUMA work (plan §3.2/§3.4) becomes **mandatory before 3D production** and lands in P4b's cluster hardening (it cannot be validated on Darwin — no affinity API — so it is a Linux-only code path exercised on the clusters). If the node-wide team ever disappoints (barrier/ticket contention at 192 threads, cross-NUMA traffic), dropping to 2 or 8 ranks per node is purely a launch-line change — the code never assumes ranks-per-node.

## 5. Decomposition and the local grid

### 5.1 Split rules

- **MPI is inter-node only: one rank per node.** Intra-node parallelism is entirely the P1 team, which spans the node's NUMA domains (§4 covers pinning and first-touch — mandatory at node width). Rationale: no MPI shared-memory traffic to tune, the fewest and largest messages, whole-node ranks match both centers' whole-node billing, and the decomposition arithmetic stays trivial. Ranks-per-node remains a pure launch-line knob — the code never assumes it — kept as the documented fallback if the team disappoints at 128–192 threads (§11.1).
- **Only φ is decomposed** — a 1D periodic ring of NTZ z-slabs. φ is periodic (no axis or physical-BC complications: with NTZ>1 the z faces simply stop being boundaries), cost-uniform (the torus is axisymmetric → near-perfect static balance across ranks, so the implicit solver's r/θ cost clustering never becomes an *inter-rank* imbalance — it stays a job for the intra-rank dynamic tiles), and z-slabs are *fully contiguous* in the AoS layout ([field.zig](../koral/field.zig)) — the basis of the zero-copy exchange (§6.2).
- **θ and r are never decomposed** (`decompose()` enforces `ntx == nty == 1`). θ-whole keeps rank-local: `correctPolaraxis` and its local-index gates, the ylo/yhi reflection BCs, and the θ-column scale-height accumulation order. r-whole keeps rank-local: every radial BC (the PUFFY outflow rescale), every shell diagnostic (`mdot`, `lum`, `radialShellIndex` — no global-index translation anywhere), and makes `toi == 0` identically (the scale-height `gix==0` quirk needs no change).
- **2D (nz==1) never decomposes** — `decompose()` requires `ntz == 1` when `nz == 1`. One modern node already beats C's 960-rank 2D production setup (plan §4.2 Phase B). Every 2D subtlety stays exactly as it is today, and MPI code paths never run.
- **The φ cap, stated honestly**: nearest-neighbor exchange requires `nz_local ≥ NG = 3` — a rank's ghost region must be fillable from its adjacent neighbor's domain alone (thinner slabs would need multi-hop halos no production code implements; C has the same per-tile ≥ NG constraint). With divisibility, the wedge production grid 384×360×32 admits NTZ ∈ {1,2,4,8}: **hard cap 8 nodes** (nz=4, at 150% φ-ghost overhead — you ship 1.5× your domain per episode), **recommended 2–4** (nz=16/8, 37.5–75% overhead, ~17k/8.6k cells per Karolina core — the strong-scaling sweet spot; P0 shows team overhead visible below ~2.2k cells/thread). Full-2π at 192 φ-cells → 24 nodes at nz=8, 64 at the hard floor; doubling φ resolution doubles the cap. That comfortably covers the currently planned science. If node demand ever exceeds it, **r-decomposition is the documented growth path** — the cart machinery is dimension-generic, and this plan's earlier φ×r design (two-stage exchange, `Cart_sub` φ-rings for shell reductions, global-index shell lookups) is recoverable from git history; nothing in the φ-only code paints over that door.
- Net effect: **the exchange is a single stage with exactly two neighbors, and no x- or y-stage code exists at all.** The wedge presets (`puffy3d*.toml`, φ∈[−π/4,π/4] periodic) need no pole-transmit; full-2π runs add it in P4c (§6.5).
- Rank layout via `MPI_Cart_create(reorder=1)` (every surveyed code except C KORAL uses it; the reorder hint is free) + `Cart_shift` for neighbors, `Cart_sub` for the φ-ring (§7.2).

### 5.2 `Decomp` and the local `Grid`

`decompose()` is pure arithmetic (unit-testable without MPI):

```zig
pub const Decomp = struct {
    global: Grid,          // global dims/extents
    local: Grid,           // nz = TNZ/NTZ; extents+dz COPIED, z-index offset via izoff (below)
    tok: i64,              // φ-slab origin (C: TOK; TOI/TOJ are identically 0 — r and θ whole)
    tk: usize,             // ring position
    ntz: usize,            // ring size
    pub fn isPhysical(d, face: BcFace) bool;   // x/y faces: always true; z faces: ntz == 1
};
```

**Implementation note (supersedes the earlier `minz = g.minz + tok·dz` sketch):** the local grid keeps the GLOBAL `minz` and stores an integer z-index offset (`Grid.izoff = tok`) that `zl()` adds inside the coordinate expression — `minz + (iz + izoff)·dz` — because a shifted-minz grid computes `(minz + tok·dz) + iz·dz`, which differs from serial's `minz + (tok+iz)·dz` by ulps and would silently break the metric-cache bit-identity that gate 3's central-bitwise claim rests on. This is exactly C's approach (`calc_xb` works on `i + TOI/TOJ/TOK`). Gate-1 unit tests pin the bit-identity on irrational extents.

Uniform divisibility (`TNZ % NTZ == 0`), the θ/r-never rules, and the 2D-single-rank rule are all enforced here with clear errors (uneven "weighted 1D cut" is a documented later option — BHAC's 3:1 cut and AMReX's `makeKnapSack`+`proposedEfficiency` are the templates, fed by the per-tile timers we already have from P0). `Grid.init` gains nothing; a second constructor `Grid.initLocal(global, origin, counts)` copies `dx/dy/dz` verbatim from the global grid (trap §1.1-1). `Sim.init` takes the local grid exactly as today — the metric cache, fields, and team never learn about ranks. `Params` grows `ntz` (default 1); the driver builds the global grid from `p.nx/ny/nz` (now global), calls `decompose`, and passes `decomp.local` plus the `Decomp` handle into `Sim.Options`.

`setBc` changes in one place: each face fill first asks `decomp.isPhysical(face)`; interior faces are skipped entirely (their ghosts come from the exchange), and `fillCorners*` runs only for physical-corner combinations (C's `mpi_isitBC_forcorners`). The `SpecificBc` callback and the PUFFY BC code are untouched — they simply only run where they should.

## 6. Halo exchange

### 6.1 Placement — exactly three sites, C-mirrored

| # | Site | Between | C |
|---|---|---|---|
| 1 | [sim.zig:1885](../koral/sim.zig) | `doCorrect()` → **exchange** → `setBc` → `opExplicit` (1st explicit) | problem.c:201 |
| 2 | [sim.zig:1912](../koral/sim.zig) | same, 2nd explicit | problem.c:317 |
| 3 | [sim.zig:1935](../koral/sim.zig) | end of step: `doCorrect()` → **exchange** → final `setBc` | problem.c:389 |
| 4 | [dynamo.zig:448](../koral/magn/dynamo.zig) | **exchange** → `calcScaleHeight` (+ its ring reduction) → `sim.setBc` → `mimicDynamo` | finite.c:1376 |

Sites 1–3 fire once per step, site 4 twice (once per `applyDynamo`) — five exchange episodes per step, which the `halo` timer row confirms (`x5.0/step`).

**Site 3 is not optional, and was missed in the first P4a cut** (found in review): `calcRijViscTotal` runs at the *top* of the next step ([sim.zig:1865](../koral/sim.zig)), *before* that step's site-1 exchange, and reads z-ghost primitives over `iz ∈ [−1, nz+1)`. Without site 3 the radiative shear viscosity — on by default in PUFFY — consumes ghosts a full RK stage stale. This is exactly why C has the third call.

C order is `do_correct → mpi_exchangedata → set_bc` (`problem.c:198-204, 314-320`; `finite.c:1376`) — exchange *before* `setBc` matters: `setBc`'s physical-corner fills then overwrite whatever the exchange deposited in ghost regions adjacent to physical boundaries, which is what makes the staged protocol's end state identical to C's (see below). Exchange `p` only (C-faithful; ghost `u` staleness between exchange points is proven tolerable by two decades of C production). Interior-ghost staleness at all *other* `setBc` call sites (inside `calcU2p` etc.) is likewise C-identical.

### 6.2 Protocol — single stage, zero-copy, persistent, pre-posted

φ-only decomposition reduces the exchange to two neighbors (φ−/φ+ on the periodic ring) — and because a φ-slab is one **contiguous block** of `Field.data` in the AoS layout, packing disappears entirely. The four slabs involved are all contiguous runs:

- send lo: domain planes `iz ∈ [0, NG)`; send hi: `iz ∈ [nz−NG, nz)`;
- recv lo: ghost planes `iz ∈ [−NG, 0)`; recv hi: `iz ∈ [nz, nz+NG)`;

each `NG·SY·SX·NV` doubles, **full ghost-extended x/y transverse extent included** (3.3% extra bytes over domain-only transverse, in exchange for zero pack/unpack code, zero buffers, and zero team involvement in the exchange). `Field.data` never moves after `Sim.init`, so **four persistent channels are bound directly to the field slabs** at `Comm.init` (`Send_init`/`Recv_init`), and an exchange episode is exactly:

1. `MPI_Startall` over all four requests (receives land straight in the ghost planes; C's send-before-recv ordering anti-pattern can't even be expressed — one call posts everything),
2. `MPI_Waitall`.

Ghost-corner content: the transmitted planes include the sender's x/y ghost columns, which hold its last `setBc` fill of the (always-physical, §5.1) x/y boundaries — one substage stale, exactly the staleness class C tolerates — and `setBc` runs immediately *after* the exchange at all three sites, re-filling every physical face and corner region it owns. The final ghost state matches serial semantics up to the documented seam-divB caveat (§1.1-8), now confined to φ seams.

Message size at production r×θ resolution (384×360, ng=3 → SX=390, SY=366, NV=13): NG·SY·SX·NV·8 ≈ **44.5 MB per direction** — deep in the bandwidth regime; at ~20 GB/s effective per link that is ~2.2 ms per message, ~13 ms of exchange per step (3 episodes × 2 directions) against multi-second 3D node-steps. Persistent requests: measured up to 37% over plain Isend/Irecv at scale, never worse (Collom et al. 2025, arXiv:2508.13370) — MVAPICH2/Omni-Path numbers; a 30-minute microbenchmark on Helios/Karolina stays on the P4a checklist. The survey's staged-vs-direct-neighbor debate (§2) is mooted by φ-only decomposition; it returns only if r-decomposition does (the two-stage φ×r design lives in this file's git history).

Two durability notes: zero-copy leans on iv-fastest AoS with z slowest — the planned AoSoA flip (P3b) preserves z-slab contiguity as long as block order stays z-slowest; record that constraint in the P3b design. And the send slabs are live field planes: nothing may write the domain edge planes between `Startall` and `Waitall` (trivially true today — the exchange is synchronous; it becomes a real scheduling constraint only in the P5 overlap work).

### 6.3 Threads and MPI

`MPI_Init_thread(MPI_THREAD_FUNNELED)` before `Team` spawn; assert `provided ≥ FUNNELED`. All MPI calls from the main thread *between* team regions — which is exactly the team's existing contract ([threading.zig:178-180](../koral/sim/threading.zig): non-reentrant, main-thread-only). The team barrier at region end is the release/acquire fence MPI needs between "pack done" and `Startall`, and between `Waitall` and unpack. THREAD_MULTIPLE is deliberately avoided (SC22 evidence: it is *the* hybrid bottleneck without VCI engineering; Cray MPICH has open MULTIPLE bugs on GH200 in 2025/26 — FUNNELED unaffected). No progress-thread tricks in Phase A; the Athena++/Parthenon `MPI_Iprobe` "progress nudge" becomes relevant only with the Phase-C poll loop.

### 6.4 Flags

Phase A: not exchanged — `cellFixup` sees ghost flags as clean, C-identical (§1.1-7). Phase C (optional, default off): the `flags` array is `cellIndex`-based like `Field`, so its φ-slabs are equally contiguous — flag exchange is just two more zero-copy persistent channels started in the same `Startall` (KHARMA's `solve_fail`-as-ghost-field model; iharm3D's separate-sync model is the anti-lesson — same episode, no extra sync). Gate: a 2-rank vs serial fixup-behavior test at field-scale tolerance, plus the flag-agreement check from the validation ladder. This closes the zig-rewrite-architecture §8.1 vs plan §4.2 contradiction with evidence on both sides of the tradeoff.

### 6.5 Pole-transmit (P4c, full-2π 3D only)

C's `TRANSMITTING_YBC`: the θ-edge rank sends its y-face *domain* slab to the tile at `(ti, tj, tk + NTZ/2 mod NTZ)` instead of a θ-neighbor. With θ undecomposed every rank is a θ-edge rank; the partner is simply rank `(tk + NTZ/2) mod NTZ` on the cart comm — with φ-only decomposition the world *is* the φ-ring (Idefix `axis.cpp` is a complete reference implementation, persistent requests included). Note the pole messages are θ-edge slabs, which are *strided* — the pack step returns for this one path (small: `NG·SX·NV` strips per z-plane), which is why it lives in P4c. Transform on the **receive** side (BHAC's factoring — send path stays uniform): θ-reversal + the sign table (VY/B2/FY flips — same table the reflection BC uses). Preconditions checked at `decompose()`: full-2π φ, NTZ even. The wedge presets never hit this path. H-AMR/KHARMA-style near-axis φ-coarsening (dt relief) is noted as a separate, later physics optimization — it attacks the axis CFL cost where communication can't.

## 7. Collectives, reductions, determinism

### 7.1 The per-step collective — exactly one

At the **end of `step()`** (after [sim.zig:1822](../koral/sim.zig) `updateEntropy`, before returning — so the driver's next `cflDt()` reads global values, §1.1-6):

```
buf = [ tstepdenmax, −tstepdenmin, @floatFromInt(n_radimp_failures_this_step) ]
Allreduce(MAX, buf[0..3])   // one call; MIN via negation
```

MAX on IEEE doubles is exactly associative → this collective is bitwise reproducible at any rank count, topology, or algorithm. It replaces C's per-step `mpi_synchtiming` (2×Barrier + Allreduce + 4×Reduce + Bcast — measured latency poison at scale). Cost ≈ 10–30 µs at 1000 ranks (log₂P × ~2 µs Slingshot pt2pt) — <0.01% of a ~300 ms step. The failure count folds in the load-bearing abort check (`n_radimp_fail` drives the C abort path) without a second collective; solver statistics print at scalar cadence via the §7.3 path, not per step.

### 7.2 Scale height (3D only)

`calcScaleHeight` accumulates per-radius partial sums; the reduction is **two `Allreduce(SUM)`s of the TNX-length arrays (Σρ√g and Σρ√g·Δθ²) *before* the sqrt/divide**, over the cart comm. With φ-only decomposition the world *is* the φ-ring, so C's world-Allreduce design (`calc_avgs_throughout`) turns out to be exactly right-sized and no sub-communicator exists anywhere in the code. With r whole, `toi == 0` identically — the `gix==0` raw-sum quirk is the existing local `ix == 0` test, unchanged. In wedge runs with NTZ=1 this is a no-op (and 2D runs are single-rank, so no comm exists there at all).

### 7.3 Init-time and diagnostic reductions

- Init fold: `Allreduce(MIN, [min_dx, min_dy, min_dz])` + `Allreduce(MAX, maxb)` for BETANORM (§1.1-5) — two calls at t=0.
- Scalars (`ScalarRow`): computed every scalar cadence, not per step. Volume sums (`totalMass`) are per-rank partials + `Reduce(SUM)` to rank 0 (which writes the file). Shell quantities (`mdot`, `lum` at `r_lum`): with r whole, every rank owns every radius — `radialShellIndex` works unchanged (the clamp concern in [scalars.zig:60-66](../koral/io/scalars.zig) is moot), each rank sums its local φ wedge at that shell, and one `Reduce(SUM)` over the cart comm finishes it. This **fixes C's gap** — C simply disables scalars under MPI (`fileop.c:112`).
- Determinism mode (wire the existing `Params.deterministic`, [params.zig:145](../koral/params.zig)): every SUM reduction switches to gather→ordered-serial-sum→bcast (rank order = fixed). MIN/MAX stay native (already exact). All SUM sites are cold (init, scale-height at 2/step, scalars at cadence), so the cost is irrelevant. Run-to-run bitwise at fixed decomposition then holds *unconditionally*; note MPICH's SUM algorithms are placement-dependent only when SMP-aware collectives kick in — determinism mode sidesteps the question entirely. Cross-decomposition bitwise identity remains explicitly out of scope (zig-rewrite-architecture §14).

## 8. I/O under MPI

### 8.1 Restart: KDMP unchanged, written collectively

The KDMP v2 body (44-byte header + `p[iz][iy][ix][iv]` global row-major, [io/dump.zig:84-107](../koral/io/dump.zig)) **is already the global-canonical layout** the survey's consensus arrives at. Under MPI:

- Header: written by rank 0 with **global** dims (the header never describes a tile).
- Body: the KDMP body is `[iz][iy][ix][iv]` global row-major — **a φ-slab is a contiguous byte range of the file**, so each rank serializes its ghost-stripped interior with the existing loop and issues one `MPI_File_write_at_all` at the closed-form offset `44 + tok·TNY·TNX·NV·8`. No file views, no `MPI_Type_create_subarray` anywhere (they return only if r-decomposition does). Read is symmetric.
- Consequences, all free: serial ⇄ MPI checkpoints are mutually readable; **restart on any rank count**; `res2kdmp` (C-restart bridge) untouched; `restart_tests.zig` keeps passing; `loadPrimDump`'s `DimMismatch` check compares against the *global* grid.
- The survey's file-view consensus stands in general, but φ-slab contiguity makes even file views unnecessary here — plain collective writes at computed offsets are the whole implementation.
- Lustre: stripe the output dir `lfs setstripe -c min(#OST, size_GB) -S 8M`; Cray-MPICH/ROMIO collective buffering aggregates to OST-aligned writers (`striping_factor` hints in the runbook). Restart file at 3D production (384×360×192×13×8 B ≈ 2.8 GB) is a comfortable collective write.

### 8.2 Viz dumps

- **Phase A**: under MPI, write KDMP only (already parallel per §8.1) + a new serial `tools/kdmp2silo` converter that reuses the existing [io/silo.zig](../koral/io/silo.zig) writer verbatim — VisIt output with *zero* MPI-Silo work.

## 10. Validation ladder (gates, in order)

1. **`decompose()` unit tests** — pure arithmetic: `tok` origins, `dz` bit-equality across ranks, `isPhysical`, divisibility errors, the θ/r-never and 2D rules. No MPI needed.
2. **1-rank MPI ≡ serial, bitwise** — the anchor. Same binary, `ntz=1`, full PUFFY step battery: every field, flag, counter, and dt bit-identical to the serial path (the exchange degenerates to no-ops; periodic self-wrap must still route through the normal BC path exactly as today).
3. **Exchange round-trip** — property test on the zero-copy channels: after one episode over a synthetic per-cell pattern, each rank's ghost planes equal its neighbors' domain planes bitwise (both wrap directions of the ring). Then a 4-rank 1×1×4 3D MINK box vs the same box serial: **interior cells bitwise for the first steps**; seam-adjacent divB at field-scale tolerance (the documented serial-corner-surface vs exact-corner-exchange difference, §1.1-8 — this is *expected*, assert the tolerance, don't chase bitwise).
4. **Run-to-run determinism** at fixed decomposition (1×1×2, 4 steps, twice): bitwise, both with `deterministic=false` (MIN/MAX only on the hot path makes this hold already) and `=true`.
5. **1×1×2, 1×1×3, and 1×1×4 vs serial** on the 3D MINK box and the puffy3d wedge preset (nz=12 divides all three), at step-golden field-scale tolerances; flags cell-for-cell away from seams.
6. **Restart cross-rank-count**: write at 4 ranks → read at 1 and at 1×1×2 → continue 2 steps → compare against an unbroken run at tolerance; serial binary reads the MPI checkpoint.
7. **Cluster smoke** (per machine, in the runbook): affinity + NUMA report (the rank prints its `sched_getaffinity` mask and each worker's `numa_node_of_cpu`), 2-node wedge strong-scale sanity, persistent-vs-Isend microbenchmark, one restart+resume cycle on Lustre.

A note on oracle limits: `tools/gen_golden.sh` compiles C in the serial no-MPI configuration — **there are no C-MPI goldens and there will be none** (C's MPI corner handling differs from its own serial mode anyway, §1.1-8). MPI validation is therefore Zig-internal (serial Zig is the reference) plus physics invariants; this is the same posture every surveyed code takes.

### 10.1 What the gate runs taught us (P4a, empirical — all C-faithful, none bugs)

1. **The central-bitwise claim holds** — on the 3D MINK box, cells ≥8 from the x/y boundaries are bit-identical to serial across φ seams after 2 forced-dt steps at 2/3/4 ranks. The exchange machinery is exact (gate 3a verifies the zero-copy channels slot-for-slot).
2. **The x/y-edge band diverges by construction, and nonlinearity amplifies it**: serial's x-z/y-z tubes copy ghost corners from the z-domain edge, C's MPI middle pass (mirrored) applies the x/y-BC at the exchanged z-ghost plane — O(field-variation-in-φ) different sources. A handful of edge cells then flip u2p/fixup/implicit branches, producing isolated arbitrary-magnitude outliers. Gates therefore bound the edge band by a **violation fraction** (≤2% over 5e-2·scale), not per-cell.
3. **The initial dt guess matches serial only to ulps**: the C-quirky min-size scan (first-seen `mdz` unless `dz < mdx`) picks a *different global cell's* per-cell spacing on a slab; the MIN fold makes all ranks agree exactly, but serial-vs-slab differ in the last bits on non-dyadic spacings.
4. **BETANORM's argmax sits in the edge band** on the 48×44×12 wedge, so the fold's `fac` shifts by ~2e-7 relative vs serial — scaling EVERY B uniformly. Any B comparison must sit above ~1e-6 of field scale.
5. **PUFFY has no seam-immune zone after stepping**: the scale height is a global per-radius sum feeding the dynamo's ΔA_φ at every θ, so edge-band differences reach seam-adjacent planes at all x/y within two steps. The radiation flux **F** — a stiff, nearly force-balanced small field — responds hardest: up to ~0.1 of its own (tiny) field scale, with a slab-periodic seam imprint. Gate 5 is therefore physics-equivalence: ≥99% of non-F slots within 1e-3·scale, F bounded at 0.2·scale, no NaNs. The ten robust variables (ρ, u, v, s, B, E) catch every real integration bug class (wrong plane ⇒ O(1) everywhere).

### 10.3 Amdahl work found by the first real multi-rank run

Running the 3-rank local rehearsal (§9) exposed two serial bottlenecks, both now threaded and both pinned by bit-identity tests. Measured on a 64×60×24 wedge, 12-core M4 Pro.

| | before | after |
|---|---|---|
| `setBc` at 3 ranks × 4 threads | 115.6 ms/step (36% of step) | ~70 ms/step |
| step at 3 ranks × 4 threads | 317.3 ms/step | ~278 ms/step |
| **initialization** at 12 threads | **30.4 s** | **4.0 s** |
| init scaling (1 / 4 / 12 threads) | 34.3 / 31.2 / 30.4 s — *no scaling* | 33.0 / 8.9 / 4.0 s |
| 60-step run, 1 rank × 12 threads | 46.6 s wall | 19.3 s wall |

1. **`fillMiddleCornersZ` was the only un-threaded `setBc` pass**, and its O((nx+ny)·ng²) cost does not shrink with slab thickness — so it grew as a *fraction* of the step with every rank added. Now band-parallel like the other face passes (x-blocks over iy, y-blocks over ix; disjoint ghost writes, domain-only reads).
2. **Initialization ignored `nthreads` entirely.** A `sample` of the init phase showed 9,273 samples parked in `__ulock_wait` (eleven idle workers) while one thread ran `puffy.lamBL`/`pow`/`log`. The metric-cache precompute (`metric/precompute.zig`, all three sweeps) and the PUFFY torus init (`prepInitDomain` + `postinit`'s β-max and scaling passes) are now threaded. The cache sweeps band over a **flattened (iz, iy) row index**, not over iz — production 2D has `nz == 1`, where banding on iz would hand the whole cache to one worker. `postinit`'s max reuses `ChunkResult.tsd_max`, whose merge is order-insensitive.

**A caveat this exercise also established, worth recording:** at this grid the 60-step trajectory is *optimization-sensitive* — identical source built ReleaseSafe vs ReleaseFast diverges by 3.9e-6 relative by step 10 (4.8e-13 at step 5), because the implicit solver's iteration-count and floor/fixup branches amplify last-bit rounding non-monotonically. So an end-to-end `t` after tens of steps is **not** a valid regression signal across code-layout changes; the C-oracle goldens (fixed binary, explicit tolerances), the nthreads-1-vs-4 bit-identity gates, and the MPI gates are.

**On single-node MPI performance:** with init no longer serial, threads-only correctly beats MPI+threads at equal core count (1 rank × 12 threads ≈ 260 ms/step vs 3 ranks × 4 threads ≈ 278 ms/step). That is the expected result and confirms the plan's premise — MPI here buys *capacity* (more nodes' cores and memory), never intra-node speed. An earlier wall-clock comparison suggesting otherwise was an artifact of the then-serial init, which MPI parallelized across processes.

### 10.4 P4b implementation record (2026-08-08 — the local half)

**MPI-IO bindings.** Six new externs (`MPI_File_open/close/set_size/write_at/write_at_all/read_at_all`) over per-family additions: `RawFile` is a POINTER in *both* families (ROMIO's `ADIOI_FileD*` — the one MPICH handle that is not an int), `RawInfo` follows the family pattern (int `0x1c000000` vs `&ompi_mpi_info_null`), `MPI_BYTE` (`0x4c00010d` vs `&ompi_mpi_byte`), `MPI_STATUS_IGNORE` (address 1 vs NULL — same `align(1)` story as STATUSES), `MPI_Offset = long long` in both, and the `MPI_MODE_*` amodes are family-invariant (shared ROMIO heritage; OMPI 5.0.9 header verified, MPICH pinned in `mpi_abi_tests.zig`). Transfers ride `MPI_DOUBLE` counts when the length is 8-divisible so a whole-body 1-rank write (2.8 GB at production) stays under the `c_int` count limit.

**Collective KDMP (§8.1, verbatim).** `dump.zig` split into header/body halves (`serializePrimBody`/`loadPrimBody`/`bodyOffset`); the driver's `writePrimDumpMpi` has rank 0 `write_at` the 44-byte GLOBAL header and every rank `write_at_all` its slab at `44 + tok·TNX·TNY·NV·8`; `loadPrimDumpMpi` is symmetric (identical-offset collective header read, then the slab), and `--restart` under MPI is enabled — the restart rebuild is exchange → set_bc → dt guess, exactly the fresh-init tail. **Gate 6** pins the load-bearing property at the byte level: (6a) the collectively-written file is byte-for-byte the serial writer's output at every rank count — which gives write-at-N/read-at-M equivalence for all N,M transitively; (6b) a serial-written file collectively read back lands every domain cell (p AND u) bitwise; (6c) restart-continue equals an unbroken run under the gate-3 claims (central bitwise — the rebuilt state is bit-identical to the initialized one, since u = p2u(p) both ways). Mutation-proven: shifting `bodyOffset` by 8 fails 6a/6b loudly on every rank.

**Scalars as reductions (§8.3).** `scalars.globalScalars` computes every calc_scalars quantity from local slab sums and folds with exactly two collectives per output row — one `Allreduce(SUM)` of [mass, mdot, radlum, totallum, Σρ√g, Σρ√gΔθ²] with the driver's diagnostic counters riding along (n_hd_fixup, n_radimp_failures, n_nan — all printed values are now true ring totals, closing the §10.2 n_radimp_fail finding), and one `Allreduce(MAX)` for pmag/ptot. The scale-height finalize reuses the pre-√ parts split out of `dynamo.scaleHeightAtIx`, so serially the folds are identity and the rows are BITWISE the pre-MPI ones. Rank 0 writes `scalars.dat`; the NaN abort decision is made from the folded count, so every rank exits together. Gate 5 now checks the folded row against serial (bulk quantities at 1e-6; mdot and β-max — an innermost-shell integral and an edge-band argmax — at 1e-3) plus ranks-agree; mutation-proven (dropping the SUM fold fails both checks, values short by exactly (ntz−1)/ntz on the φ-uniform torus).

**Gates hardening.** The harness gained the driver's `errdefer MPI_Abort` guard: the offset mutation exposed that a rank-local gate error (bad slab → `initCell` failure on one rank) stranded the peers in the next collective — the same failure class §10.2-2 fixed in the driver.

**kdmp2silo (§8.2 Phase A).** `tools/kdmp2silo.zig <params.toml> <kdmp|dir> [out]` replays checkpoints through the unchanged `io/silo.zig` writer. To make the replayed configuration exactly the run's, `applyPhysicsOverrides` and the Options construction moved from the driver into `puffy.zig` (`puffy.simOptions`) — one code path for both. Verified: a 3-rank-written 3D checkpoint converts to a 15.7 MB PDB `.silo`.

**Node-width hardening (the P1 deferral).** `pin_threads` (params → `Sim.Options` → `Team.init`): on Linux each team thread (main = first, helper i = (i+1)-th) binds to one cpu of the `sched_getaffinity` mask — the cgroup cpuset Slurm grants the rank, so the binding stays inside the allocation by construction; per-rank confirmation line; inert on macOS. Field/FaceStore gained `initUninitialized` and `Sim.init` zeroes all big per-cell stores via `threading.parallelZero`, so the first touch of every page lands on a worker (parallel first-touch; the metric cache and torus init were already threaded in §10.3). Cross-compiles clean for `x86_64-linux-gnu.2.28`. **The efficacy numbers at 128 (Karolina) / 192 (Helios) threads are cluster work — nothing at 12 laptop threads can stand in for them.**

**Heartbeat.** ntz>1 adds `mpi=…%` — (halo+collect)/total stepping time since the last output row, from the PassTimers buckets (measured 1.7% on the local 3-rank 64×60×12 demo).

**End-to-end demo (local, 3 ranks × 2 threads, 64×60×12):** fresh run → collective checkpoints + rank-0 scalars.dat; restart at 3 ranks (collective read) continues 10→20; the plain SERIAL binary restarts from the 3-rank-written file and continues, ending within 1.8e-6 of the 3-rank continuation's `t` (mass to 6e-11; the luminosity column differs ~20% — it is an F-field integral over a near-zero early transient, squarely §10.1-5's documented F sensitivity). `kdmp2silo` converts the MPI-written frames.

**Verification at this state:** serial suite 236 pass / 0 fail; serial binary has zero MPI symbols; both ABI families compile (`-Dmpi-family=mpich` builds clean); gates 1–6 green at 1/2/3/4 ranks; slow C-oracle goldens unchanged.

### 10.5 P4b code review (2026-08-08) — findings and fixes

A second review pass over the P4b change set produced four findings, all fixed — and a third pass over *those fixes* (§10.5.1) found that the most important one did not work, which is the part of this section worth reading.

**1 (real bug — a truncated checkpoint restarted silently).** `loadPrimDumpMpi` passed `MPI_STATUS_IGNORE` and sized the transfer by its own buffer, so a short file returned `MPI_SUCCESS` having filled only part of it; `loadPrimBody`'s `Truncated` guard could never fire because the buffer is *allocated* at exactly `primBodySize`. The tail then entered `initCell` as uninitialized heap. **Reproduced**: a checkpoint truncated by 200 KB — the walltime-kill case — restarted "successfully" at 3 ranks and died one step later as `NanInFlux`, pointing the blame at the physics; the serial path rejected the same file cleanly with `Truncated`. The exposure is worse than it looks because `--restart <dir>` selects the *newest* checkpoint, which is precisely the file a kill leaves partial.

Fixed with an `MPI_File_get_size` check before the header read and again after the dims are validated. **Size, not a per-transfer status count, is the load-bearing choice**: every rank gets the same number and therefore the same accept/reject decision, so the ring leaves as one. A per-rank count would let one rank error out of the sequence while its peers advance into the next collective — trading a corrupt restart for a job-wide hang. (`MPI_File_get_size` is a query, not a collective, but calling it on every rank is correct under either reading.) Post-fix all three ranks report `Truncated` and abort together, while an intact checkpoint restarts to the same `t` bit-for-bit. Pinned by **gate 6d**, mutation-proven (disabling the guard ⇒ "truncated checkpoint was accepted" on every rank).

**2 (hang risk).** `writePrimDumpMpi` returned `void` with three `catch return` exits (per-rank `alloc`, `bufPrintZ`, `fileCreate`) around a collective sequence — a rank taking one would strand its peers in `MPI_File_open`/`write_at_all`, and because the function was infallible the driver's `errdefer abortJob` could never fire. Now `!void`, `try`'d at both call sites, so a rank-local failure aborts the job instead of hanging it — the same discipline §10.2-2 established.

**3 (misleading diagnostic).** The ~1 Hz heartbeat printed rank-0-local failure and fixup counts while `znps` was deliberately global, so a blow-up confined to another rank's φ-slab read as `fail# 0 0 0`. The heartbeat cannot simply fold: it runs under `if (is_root and <wall-clock throttle>)`, so a collective there would be entered by one rank alone and deadlock instantly — a trap now spelled out in the function's doc comment. Instead the driver accumulates the *already-folded* `n_radimp_fail_step` on the every-rank path (free — the fold happens inside `step()`), prints that as the leading `fail#`, and marks the genuinely rank-0 columns `(r0)`. Exact global counters remain in `scalars.dat`.

**4 (build ergonomics).** `-Dmpi-lib` alone still reported "no mpicc found and **no -Dmpi-lib given**"; the actual blocker is an undetectable ABI family. The message now distinguishes the two cases and names `-Dmpi-family`/`-Dmpi-include`.

#### 10.5.1 Round two — the fixes themselves reviewed (adversarial, 2026-08-08)

Fix 1 above was then attacked by a 5-lens / 31-agent adversarial pass (each candidate defect put to two independent skeptics). **It found that fix 1 did not actually close the case it was written for**, plus a second hang of the same class as fix 2. Both are now fixed and gate-pinned; the lesson is recorded here because the failure mode is subtle and general.

**1b — the size guard was inert for this program's OWN checkpoints.** `fileCreate` calls `MPI_File_set_size(fh, total)` right after the collective open — necessary, because MPI has no truncate-on-open mode and a stale longer file must be cut back. But that sets the file to its FINAL length before a single body byte is written, so a checkpoint interrupted mid-write is **full-length with unwritten regions reading back as zero holes**. No length-based check can ever distinguish it from a complete one. The guard therefore only covered files short in *length* (serial-written checkpoints, partial copies) — while the motivating scenario, a walltime kill during the collective write, sailed straight through it. Gate 6d could not see this because it fabricates its truncated fixture with `std.Io.writeFile` on a shortened buffer, i.e. only the length-short case.

Fixed by making the **44-byte header a completion marker**: the writer now emits body → `MPI_File_sync` → header, so an interrupted checkpoint has no valid magic and `parseDumpHeader` rejects it with `BadMagic` on every rank. The sync is what gives the marker meaning — without it the header may reach storage while the body it describes has not. It is not free (it forces the body out to storage before the header is written), but that flush is precisely what a checkpoint is for, and it is one per output frame against a multi-GB write; measure it on Lustre alongside the striping settings in §8.1 rather than assuming. The final bytes are unchanged, so serial⇄MPI byte-identity (gate 6a) still holds. Pinned by **gate 6e**, which creates a pre-sized empty file and requires rejection; mutation-proven by restoring the old header-first order in the fixture, which makes 6e report "interrupted checkpoint was accepted" on every rank — i.e. a full-length file with a valid header and a zeroed body loading silently, exactly the pre-fix hazard.

**2b — a rank-local allocation between two collectives.** `loadPrimDumpMpi` (and the gates' `readKdmpCollective`) allocated the slab buffer *after* the collective `fileOpenRead`. A rank-local OOM there unwinds through the `defer`red collective `fileClose` while the peers block in `read_at_all` — a hang the driver's `errdefer` cannot rescue, because the failing rank never reaches it. Fixed by hoisting every rank-locally-fallible step above the first collective; from the open onward, every remaining failure derives from bytes all ranks read identically, so the ring always leaves together.

**Also hardened from the same pass:** a `MPI_Abort`-then-`unreachable` in `check()` (UB in ReleaseFast if `MPI_Abort` ever returns) → `std.process.exit`; `rwCount`'s range `assert`s, compiled out in exactly the ReleaseFast builds that write production checkpoints, → a hard check that aborts loudly instead of an overflowing `@intCast`; the startup window between `MPI_Init_thread` and the driver's `errdefer abortJob`, where a rank-local failure (an unreadable params file or opacity table on one node) would run `MPI_Finalize` — a job-wide fence — while peers advanced into `MPI_Cart_create` → a new `Comm.abortWorld` armed immediately after `initWorld`; and a per-rank restart-path divergence (each rank resolves `--restart <dir>` independently, which only agrees if every node sees the same directory) → a MAX/MIN fold of the loaded header, turning a silent cross-rank desynchronization into a clean `RestartRankDisagreement`.

**Accepted, not fixed:** `resolveRestartPath` takes the lexical maximum over *all* `*.kdmp` names, so a foreign `.kdmp` sorting after `prims#####.kdmp` would win. Pre-existing, documented behavior, and out of P4b's scope.

**The generalizable lesson:** a length check cannot validate a file whose writer preallocates. Where a format must survive interruption, the validity marker has to be *written last and after a sync* — and the regression test must construct its fixture through the real writer's mechanism, not by truncating a buffer, or it will pass while the actual failure mode goes uncaught.

Reviewed and found correct, worth recording because they are the load-bearing claims: halo tag/neighbour pairing including the `ntz==2` self-aliasing case, the zero-copy slab offsets against `Field`'s iz-slowest AoS layout (and that `p.data` is only copied, never swapped), `Grid.izoff` routing through every z-coordinate helper, all four exchange sites, the end-of-step `Allreduce(MAX)` sign handling for `tstepdenmin`, the init `min_d*` fold, scale-height reduction ordering, `bodyOffset` tiling, both families' ABI constants and Status layouts, `sched_setaffinity` usage, and the threaded metric-cache/postinit/prepInit passes for cross-band write hazards (none — `applyKrisCorrection` recomputes rather than reading the cache).
